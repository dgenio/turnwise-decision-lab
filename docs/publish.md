# Publish `dgenio/turnwise-decision-lab`

The repository is prepared locally as a public-source release candidate. GitHub publishing requires a repository-creation action in an authenticated `dgenio` account. The connected GitHub actions used here can write to **existing** repositories, but do not expose creation of a brand-new repository. No GitHub URL, stars, workflow success or Pages deployment should be claimed before the resource exists and is verified.

## Create once (GitHub web)

Go to https://github.com/new using the intended account:

- Owner: `dgenio`
- Repository: `turnwise-decision-lab`
- Description: `Route the work, not just the model — a falsifiable per-turn AI execution and context experiment.`
- Visibility: Public
- No autogenerated README, .gitignore or license (they are in the archive).

**Naming note:** the word Turnwise is already used by unrelated AI evaluation projects. The repo name includes a specific research-lab suffix; don't register a `turnwise` package or imply brand exclusivity.

## Push the release files

From inside the extracted `turnwise-decision-lab` folder, check the static site and tests before pushing:

```bash
python -m unittest discover -s tests -v
python -m turnwise_lab.live_demo --output reports/live-local-run.json
python -m turnwise_lab.benchmark
python -m scripts.render_local_demo

git init -b main
git add .
git commit -m "Publish Turnwise decision-lab v0.4 research exhibit"
git remote add origin https://github.com/dgenio/turnwise-decision-lab.git
git push -u origin main
```

GitHub Desktop's "Publish repository" feature is an alternative. Do not put API keys in source or commit an environment file. For the source repository, keep `demo/` + `reports/` + `fixtures/` visible; do not upload only screenshots.

## Publish the interactive demo

Enable Repository **Settings → Pages → Build and deployment → GitHub Actions**. The included `.github/workflows/pages.yml` uploads `demo/`, including a copy of the receipt JSON. After GitHub reports a successful deployment, check the actual Pages URL and add it to the README and About description. Don't guess the URL.

## Before the first public announcement

Verify the repository and Pages from an unsigned-in browser, and ask one external engineer to run the 3-line quickstart and independently inspect at least one failure case. The first communication should be "here's what the experiment measured and why the simpler solution won this test," not "we built a better model router." Use the author's earlier LinkedIn/Substack hypothesis as background, and link verified public artifacts only.
